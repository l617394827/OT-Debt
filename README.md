# OT-Debt · 加班清算单

> 把深夜消息、临时修改和漫长等待，清算成一张有证据、有数字、也有脾气的账单。

OT-Debt 是一个使用 TypeScript 构建的纯前端小工具。它不会只告诉你“加了多少班”，而是尝试分辨哪些时间花在了等待、临时需求、反复修改和非工作时段会议上，并生成一份可查看、可沟通、可分享的加班清算单。

## 为什么做这个项目

大多数加班工具解决的是“记工时”，OT-Debt 更关心“这笔班为什么会发生、是否值得发生”。

- 让散落在聊天记录里的隐形付出被看见
- 区分必要处置与流程、沟通造成的无效加班
- 把模糊的疲惫转成时间、金额和生活损耗
- 用不同语气把同一组事实整理成可沟通的话
- 帮助使用者重新确认自己的工作与生活边界

## 功能特性

- 支持本地规则与 OpenAI 兼容接口两种分析方式
- 内置“稳健取证”“平衡清算”“深挖隐形加班”三套 AI 提示词
- 通过弹窗提供企业微信、钉钉、飞书的完整对话导出指引与关键截图
- 可一次导入多份 `.txt`、`.md`、`.html`、`.csv` 或 `.json` 文件并合并去重
- 手动补录日期、起止时间、原因与证据
- 自动区分无效加班和必要处置
- 计算总时长、无效占比、折算金额与班味浓度
- 首页未清算时显示 ？？%，清算后回写当前月份的真实班味数据
- 支持“毒舌满格”“据理力争”“体面辞职”三种口吻
- 一键复制沟通话术
- 打印完整清算单
- 下载 9:16 PNG 分享卡片
- 无账号、无内置后端；规则模式不上传数据，AI 模式仅发往用户指定的接口

## How to Use

### 1. 安装与启动

环境要求：

- Node.js 18 或更高版本
- npm 9 或更高版本

克隆项目并安装依赖：

```bash
git clone <your-repository-url>
cd OT-Debt
npm install
```

启动开发服务：

```bash
npm run dev
```

终端会显示本地访问地址，通常为：

```text
http://localhost:5173/
```

### 2. 导出并导入完整对话

进入“聊天记录”区域后选择 **企业微信、钉钉或飞书**，再点“查看完整导出指引”。长步骤、权限边界、关键界面截图和原始资料链接都放在弹窗里，不占用主页面。

| 软件 | 完整对话的现实路径 | 可解析格式 |
| --- | --- | --- |
| 企业微信 | 个人端迁移只生成加密 `.bak`；需管理员通过“会话内容存档”提供可读记录 | TXT、CSV、JSON |
| 钉钉 | 普通客户端没有已核实的一键完整导出；需管理员开启钉钉官方 DWS 并授权导出 | JSON、TXT、CSV |
| 飞书 / Lark | 桌面端多选消息，每批最多 100 条，导出到文档后下载为 Markdown | Markdown、TXT、JSON |

> 重点：本工具要的是完整对话，不要求用户先筛选“关键消息”。飞书长对话可分成多份 Markdown；企微和钉钉则必须尊重企业权限，由管理员提供完整记录。

#### 方式 A：一次拖入多份文件

把完整对话的所有分段文件一起拖到上传区域，或点击该区域多选文件。

- 一次最多 50 份，单份不超过 25 MB，合计不超过 100 MB
- 支持 TXT、Markdown、HTML、CSV 和 JSON
- 多份文件会自动合并并去掉重复消息
- CSV 建议保留“发送时间、发送人、消息内容”等表头
- JSON 会自动寻找时间、发送者和正文相关字段
- 企业微信 `.bak` 是加密迁移包，会被明确拦截并解释原因

#### 方式 B：粘贴完整文本

如果管理员直接给了文本，或你已把完整会话整理成纯文本，可粘贴到输入框。例如：

```text
2026-09-03 21:30 产品同事：首页按钮再换个橙色，明早要看
2026-09-03 23:00 我：第六版已经发了
2026-09-10 20:00 项目群：先等审批，稍后再给排期
2026-09-10 22:30 我：审批还没下来
```

解析器会重点寻找日期、时间、工作信号与收工信号；完整文本中的普通聊天会保留在输入框中，但只把符合清算条件的时段计入账单。
#### 方式 C：手动补录

没有时间戳、解析不准或不方便复制的记录，可以在“手动补一笔”区域填写：

1. 加班日期
2. 开始与结束时间
3. 加班类型
4. 一句证据或说明

点击“记入这笔账”后，可以继续添加下一笔记录。录错的条目可在待清算列表中删除。

### 3. 选择分析方式

导入对话后，在“谁来翻这本旧账？”区域选择一种方式：

| 方式 | 特点 | 数据去向 |
| --- | --- | --- |
| 规则模式 | 默认启用、速度快、免费，依赖日期、时间和关键词 | 只在当前浏览器处理 |
| AI 模式 | 能关联上下文，识别等待、返工和任务完成消息 | 发往你填写的兼容接口 |

#### 接入 OpenAI 兼容模型

1. 点击“配置 AI 接口”。
2. 填写兼容接口地址。可填写以 `/v1` 结尾的基础地址，也可直接填写完整的 `/chat/completions` 地址。
3. 填写服务商实际提供的模型 ID。
4. 填写服务商提供的 API Key；无鉴权的本地或自建接口可以留空。
5. 选择提示词版本，然后点击“测试并启用 AI”。
6. 测试通过后页面会自动切到 AI 模式，直接点击“开始清算”即可。

内置提示词版本：

| 版本 | 适合场景 |
| --- | --- |
| 稳健取证 | 更在意少误判、需要拿结果正式对账 |
| 平衡清算 | 默认推荐，兼顾完整度与误判率 |
| 深挖隐形加班 | 希望额外找出等待、待命、反复修改和深夜会议 |

长对话会按行自动分段，每段保留少量上下文重叠，完成后合并去重。当前单次最多处理约 24 万字符；更长记录建议按上、下半月分开。

> 本工具使用 OpenAI 兼容的 Chat Completions 请求格式，可连接提供该协议的模型服务。API Key 通过 `Authorization: Bearer <API_KEY>` 发送，只保存在当前页面内存，不写入 `localStorage`、仓库或日志，刷新页面后即清除。公开部署时仍建议通过自己的服务端代理保护长期密钥。

### 4. 设置折算时薪

在页面底部填写用于估算时间价值的时薪。清算单会根据无效加班时长计算“无偿垫付”金额。

该金额只用于个人记录和沟通参考，不代表法定加班费计算结果。

### 5. 生成清算单

点击“开始清算”。页面会生成：

- 本月加班总时长
- 无效加班时长与占比
- 无偿垫付金额
- 班味浓度与等级
- 每笔加班的证据和清算意见
- 电影、晚饭、睡眠等人生损耗换算

如果没有识别出记录，请检查输入是否同时包含时间和工作关键词，或改用手动补录。

### 6. 切换表达方式

清算单顶部提供三种口吻：

| 模式 | 适用场景 |
| --- | --- |
| 毒舌满格 | 自己解气、朋友间分享、传播卡片 |
| 据理力争 | 与负责人沟通排期、调休或补偿 |
| 体面辞职 | 梳理离职表达与工作边界 |

切换模式后，逐条清算意见、诊断总结和复制话术会同步变化。

### 7. 导出结果

- **复制甩脸话术**：复制当前语气对应的完整沟通文案
- **下载 9:16 卡片**：生成适合手机分享的 PNG 图片
- **打印清算单**：调用浏览器打印功能，可另存为 PDF

## 输入识别说明

规则模式使用浏览器内的日期、时间与关键词解析；AI 模式把完整对话分段发送到用户配置的 OpenAI 兼容接口，再校验模型返回的日期、时间、分类和证据。无论使用哪种方式，都建议：

- 每条消息保留明确的日期和时间
- 不要删除“修改”“审批”“会议”“故障”等上下文词
- 对识别不准或缺少结束时间的记录使用手动补录
- 生成后再次核对时长、类型和证据原文

必要线上事故会被标记为必要处置；等待、反复修改、非工作时间会议和临时安排通常会被判定为无效加班。

## 隐私与安全

- 规则模式下，聊天内容不会离开当前浏览器
- AI 模式下，聊天内容会发送到用户主动填写的接口；使用前请确认服务商的数据政策与企业合规要求
- 项目没有账号系统和后端数据库
- 页面不会持久化保存输入内容或 API Key
- 推荐通过自己的服务端代理持有长期 API Key，不要把长期密钥填入公开部署的网页
- 刷新或关闭页面后，当前记录会消失
- 分享前请自行检查并遮盖公司名、人名与业务信息

> 本项目是情绪疏导与个人记录工具，不构成法律、劳动仲裁、薪酬或医疗建议。重要证据请保留原始文件。

## 项目结构

```text
OT-Debt/
├─ public/guides/    # 三平台导出指引截图与来源说明
├─ src/
│  ├─ ai.ts          # OpenAI 兼容请求、提示词与结构化结果校验
│  ├─ importers.ts   # TXT / Markdown / HTML / CSV / JSON 解析与格式识别
│  ├─ main.ts        # 页面结构、清算规则与全部交互
│  └─ style.css      # 视觉系统、响应式和打印样式
├─ index.html        # HTML 入口
├─ package.json      # 项目信息与命令
├─ tsconfig.json     # TypeScript 配置
└─ README.md         # 项目说明与使用文档
```

## 技术栈

- TypeScript
- Vite
- 原生 DOM API
- Canvas API
- CSS 响应式布局与打印样式

项目没有引入前端框架和 UI 组件库，便于快速运行、阅读与二次开发。

## 当前限制

- 规则模式依赖固定关键词；AI 模式的准确率、费用与速度取决于用户选择的模型
- 未直接接入企业微信、钉钉或飞书账号，完整会话仍受企业权限限制
- 不支持自动读取历史聊天记录
- 项目不自带安全代理；公开部署 AI 模式前，需要自行准备服务端代理与访问控制
- 部分模型接口未开放浏览器跨域访问，必须通过代理调用
- 无服务端存储和跨设备同步
- 分享卡片暂未提供自动打码功能
- 折算金额不等同于劳动法意义上的加班费
